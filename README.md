# Telegram LM Studio Bot

Telegram-бот, который подключается к локальной языковой модели через LM Studio и отвечает на сообщения в чатах.

## Возможности

- **Подключение к LM Studio** — работает с любой моделью, запущенной локально через LM Studio API
- **Триггеры в группах** — бот реагирует на:
  - Упоминание `@username` бота
  - Реплаи на сообщения бота
  - Прямое обращение по ключевым словам (настраивается)
- **Лесенка** — в групповых чатах бот склеивает последовательные сообщения пользователя в одно, чтобы модель видела весь контекст
- **Симуляция печати** — бот показывает статус "печатает" с реалистичными задержками:
  - Задержка реакции (2.5–4.5с) — имитирует время, за которое человек замечает сообщение
  - Задержка по кол-ву символов — имитирует время набора текста
  - Фоновый typing-индикатор каждые 30 секунд во время генерации ответа
- **Ограничение частоты** — рандомная задержка перед ответом в группах, чтобы бот не спамил
- **Разделение на чанки** — длинные ответы разбиваются на сообщения по 4000 символов
- **Контекст чата** — история последних N сообщений сохраняется в памяти

## Установка

### Требования

- Python 3.10+
- LM Studio с запущенным локальным сервером (по умолчанию `http://localhost:1234`)

### Быстрый старт

```bash
git clone <repo-url>
cd tg-lmstudio-bot
```

Создай файл `.env` на основе `.env.example`:

```bash
BOT_TOKEN=your_telegram_bot_token
LM_STUDIO_URL=http://localhost:1234
MODEL=qwen/qwen3.6-27b
TEMPERATURE=0.7
MAX_HISTORY=20
SYSTEM_PROMPT=Твой системный промпт здесь
```

### Запуск

**Вариант 1: напрямую**
```bash
python3 main.py
```

**Вариант 2: systemd-сервис**
```bash
# Скопируй сервисный файл
cp tg-lmstudio-bot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user start tg-lmstudio-bot
systemctl --user enable tg-lmstudio-bot  # автозапуск
```

Управление сервисом:
```bash
systemctl --user restart tg-lmstudio-bot   # перезапуск
systemctl --user status tg-lmstudio-bot    # статус
journalctl --user -u tg-lmstudio-bot -f    # логи в реальном времени
```

## Конфигурация

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather | — |
| `LM_STUDIO_URL` | URL локального API LM Studio | `http://localhost:1234` |
| `MODEL` | Название модели в LM Studio | `qwen/qwen3.6-27b` |
| `TEMPERATURE` | Температура генерации (0.0–1.5) | `0.7` |
| `MAX_HISTORY` | Кол-во сообщений в истории контекста | `20` |
| `SYSTEM_PROMPT` | Системный промпт для модели | `Ты — полезный ассистент.` |

## Структура проекта

- `main.py` — основной файл бота (aiogram, LM Studio API, логика триггеров)
- `phrases.py` — фразы для неактивности (когда бот "не в сети")
- `.env` — конфигурация (не коммитится, в `.gitignore`)
- `.env.example` — шаблон конфигурации
- `tg-lmstudio-bot.service` — systemd-сервис для автозапуска

## Как это работает

1. Бот получает сообщение через Telegram long polling
2. Проверяет, является ли сообщение триггером (упоминание, реплей, ключевое слово)
3. Если триггер — ждёт случайную задержку (чтобы не спамить)
4. Собирает контекст из истории чата
5. Отправляет запрос к LM Studio API
6. Показывает "печатает" с реалистичными задержками
7. Отправляет ответ в Telegram
