# tg-lmstudio-bot

Telegram-бот на aiogram 3, работающий от имени Bot API аккаунта. Подключается к локальной LLM через LM Studio, отвечает в личных сообщениях и групповых чатах в заданном стиле. Использует TF-IDF RAG на основе истории реальных переписок для стилизации ответов.

---

## Стек

| Компонент | Назначение |
|-----------|-----------|
| [aiogram 3](https://github.com/aiogram/aiogram) | Async Telegram Bot API фреймворк |
| [LM Studio](https://lmstudio.ai) | Локальный LLM-сервер, OpenAI-совместимый API |
| scikit-learn / TF-IDF | RAG-поиск по истории переписки |
| python-dotenv | Конфиг через `.env` |
| systemd (user) | Автозапуск и перезапуск |

---

## Структура проекта

```
tg-lmstudio-bot/
```

## Установка

### 1. Зависимости

На Arch/CachyOS:

```bash
yay -S python-aiogram python-dotenv python-requests python-scikit-learn python-numpy
```

На Ubuntu/Debian:

```bash
pip install aiogram python-dotenv requests scikit-learn numpy scipy
```

### 2. Создать бота

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot`
2. Получить `BOT_TOKEN`

### 3. Конфигурация

Создать `.env` в папке проекта:

```env
# Telegram Bot Token от @BotFather
BOT_TOKEN=1234567890:ABCdef...

# LM Studio
LM_STUDIO_URL=http://localhost:1234
MODEL=auto          # auto = первая загруженная модель
TEMPERATURE=0.7

# История диалогов (количество сообщений user+assistant в памяти)
MAX_HISTORY=20

# Количество последних сообщений всех участников, попадающих в контекст
GROUP_CONTEXT_SIZE=20

# Системный промпт (без RAG-контекста)
SYSTEM_PROMPT=Ты — лиса...

# Системный промпт когда RAG нашёл похожие примеры
SYSTEM_PROMPT_RAG=Ты — лиса... Ниже — твои реальные фразы...

# Факт о себе — инжектируется только если вопрос касается местоположения
USER_FACTS=сейчас живёт во вьетнаме, не в России
```

### 4. RAG-индекс (опционально)

Улучшает стиль ответов, используя реальную историю переписки как примеры.

**Подготовка:** экспортировать историю чатов из Telegram Desktop в формате JSON (`result.json`), положить в папку проекта.

```bash
python build_rag.py
```

Без индекса бот работает с обычным системным промптом.

## Запуск

### Напрямую

```bash
python main.py
```

### Через systemd (автозапуск)

Создать `~/.config/systemd/user/tg-lmstudio-bot.service`:

```ini
[Unit]
Description=Telegram LM Studio Bot
After=network.target

[Service]
WorkingDirectory=/home/<user>/projects/tg-lmstudio-bot
ExecStart=/usr/bin/python3 main.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now tg-lmstudio-bot
```

Управление:

```bash
systemctl --user restart tg-lmstudio-bot   # перезапустить
systemctl --user status  tg-lmstudio-bot   # статус
journalctl --user -u tg-lmstudio-bot -f    # живые логи
```

## Как работает

### Триггеры (в порядке приоритета)

| Триггер | Условие |
|---------|---------|
| **Тег бота** | `@botusername` в начале сообщения |
| **Личное сообщение** | Любое сообщение в ЛС |
| **Вопрос** | Сообщение оканчивается `?` пока активен онлайн-режим |
| **Реплай** | Ответ на сообщение бота |
| **Слово-триггер** | Сообщение начинается с `TRIGGER_WORD` (по умолчанию «лиса») |
| **Followup** | Следующее сообщение от того же пользователя в течение 60 секунд после ответа |
| **Случайный онлайн** | 50%→10%→5% убывающий шанс во время онлайн-окна |

### Онлайн-режим

После каждого ответа активируется **10-минутное онлайн-окно**:
- Прямые триггеры отвечают мгновенно
- Случайные сообщения могут получить ответ с убывающей вероятностью

### Задержки ответа в группах

| Ситуация | Задержка |
|----------|----------|
| Тег, вопрос, followup, онлайн-режим | 0 сек |
| 20% шанс «быстрый» | 0 сек |
| 80% шанс «отложенный» | 3–10 минут |

Дополнительно: реакция 2.5–4.5 сек + typing по скорости печати.

### Лесенка

При followup-триггере бот ждёт 10 секунд после последнего сообщения, собирает все сообщения подряд и склеивает в один запрос. Моделирует людей, которые пишут мысль несколькими сообщениями.

### Групповой контекст

Скользящий буфер из последних `GROUP_CONTEXT_SIZE` сообщений всех участников инжектируется в системный промпт. Бот «видит» о чём говорили, даже если к нему не обращались.

```
--- Последние сообщения в чате ---
[Иван]: что делаешь вечером
[Маша]: кто-нибудь смотрел этот фильм
[лиса]: не смотрела, но слышала что норм
---
```

### Split-message

С вероятностью 30% бот отправляет два отдельных сообщения. Второе — короткое дополнение (3–8 слов), как будто вспомнила деталь. Пауза 1–3 сек + typing между сообщениями. Оба ответа записываются как одна запись в историю.

### RAG (Retrieval-Augmented Generation)

1. Запрос нормализуется и векторизуется TF-IDF
2. Ищутся top-8 похожих примеров (порог сходства ≥ 0.20)
3. Найденные примеры добавляются к системному промпту как «твои реальные слова»
4. Это заставляет модель держаться реального стиля переписки

### Idle-сообщения

Через 4 часа ± 10 минут без активности бот отправляет случайную фразу из `phrases.py`. Не отправляет, если последнее сообщение уже было от бота.

### Автовыбор модели

При `MODEL=auto` запрашивает `/v1/models` у LM Studio при старте и берёт первую загруженную. Чтобы сменить модель — перезагрузить в LM Studio → перезапустить сервис.

## Структура промпта

```
[Системный промпт + RAG примеры (если найдены)]
[Факт о местоположении (только при релевантном вопросе)]

--- Последние сообщения в чате ---
[Участник1]: текст
[лиса]: предыдущий ответ бота
---

[История диалога: пары user/assistant]
[Текущее сообщение пользователя]
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Telegram Bot Token (обязательно) |
| `LM_STUDIO_URL` | — | URL LM Studio, напр. `http://localhost:1234` |
| `MODEL` | `auto` | ID модели или `auto` |
| `TEMPERATURE` | `0.7` | Температура генерации |
| `MAX_HISTORY` | `20` | Глубина истории диалога |
| `GROUP_CONTEXT_SIZE` | `20` | Размер буфера группового контекста |
| `SYSTEM_PROMPT` | — | Системный промпт без RAG |
| `SYSTEM_PROMPT_RAG` | — | Системный промпт с RAG |
| `USER_FACTS` | — | Факт о себе (инжектируется при вопросах о локации) |

## Устранение проблем

**Модель не найдена при старте:**
```
LM Studio не вернул ни одной модели
```
→ LM Studio должен быть запущен, хотя бы одна модель загружена.

**Бот не отвечает на триггер в группе:**
→ Проверить логи. Возможно, активна задержка 3–10 минут (вне онлайн-режима).

**Ошибка `Polling stopped`:**
→ `systemctl --user restart tg-lmstudio-bot`
